What's new in flua — 0.1.138 through 0.1.173

Thirty-six releases in a little over a month — the repo changelog has the details; this is the human version of what actually changed and why you should care. The short version: flua grew a QA builder, the simulator became a test bench with buttons and sliders, the controller gained a read-only safety mode, and the thing agents need — knowledge they can retrieve and trust — got a first-class surface. Most of it was built against real field reports, so almost everything here exists because someone hit a wall first.

The big one: a QA builder on top of the engine

The engine stays the product — but the releases from 0.1.161 on add the first app on top of it, for the people who will never write Lua: a recipe library plus flua --tool build, a browser page that turns recipes into finished QuickApps.

  • Pick a recipe, pick your devices. Six templates (motion lights, fan on humidity, heater on cold weather, leak alert, door notification, light at sunset) with categories; the device pickers read your real HC3 and filter by the type inheritance tree, so a flood sensor shows up where a binary sensor is expected. No HC3, or the sensor not installed yet? Pick a simulated device instead — the whole loop works on your laptop.
  • Simulate before you upload. The generated QA runs in the sim on a 600× clock, with your picked devices seeded as simulated devices — plus any world devices the recipe declares, like the weather manager with its sliders. View UI opens the HC3-style web view of the running QA in a new tab.
  • Every recipe proves itself. Each template carries a declarative verify scenario (breach the sensor, drag the slider, check the result) that runs in a couple of seconds — flua --tool build --verify-all — and CI gates template changes on it. A faulty template cannot ship.
  • Recipes are controller-correct Lua. Device actions through fibaro.call, variables read in onInit, threshold sliders that sync with quickAppVariables both ways, and the reactive ones subscribe to the refreshStates event feed — a breach lights the room instantly, not after a poll. Status: a parked proof of concept, delimited by its own decision record (ADR 0015).

The simulator became a test bench

  • Simulated devices got user interfaces. Every binary sensor in the bundled set has Breach/Clear buttons in the web view; every multilevel one a slider over its real range and unit. Tap the motion sensor, watch the light QA react — the view doubles as the test rig.
  • The weather is drivable. The weather manager's sliders write /weather; a heater recipe reads the same endpoint a real HC3 serves, so the QA runs identically on the controller.
  • Everything is mockable from plain Lua. The Skoda pair (control QA + a MyŠkoda API mock) and the Modbus server demo ship as living fixtures — write the far side as a sim QA speaking the real protocol, and the integration is testable offline.

Safety: read-only modes for the live controller

  • --%%mode:readonly — reads behave exactly like online mode; any write that would reach the HC3 is refused with 403 before it leaves. Sim-owned writes still work, so you lose nothing.
  • --%%mode:readonly+call — one deliberate unlock: fibaro.call actions pass through, so test code can flip a light on and off to see it work, while creating or deleting anything stays blocked.

The agent environment — the part that compounds

Most releases in this stretch were about making flua a better place to be for coding agents, and the pieces now connect:

  • The capabilities index. flua --tool caps — 40 curated knowledge entries (quirks, idioms, how-tos), every one pinned to the test that proves it, plus a machine-derived half (the 28 tools, the sim devices, the REST route table with real/stub status). caps --search "websocket push" answers the questions agents used to dig through Python source for. The same content ships in the wheel and doubles as MCP resources.
  • The feedback loop, tooled. flua --tool feedback new scaffolds a dated experience report; feedback publish files it as a GitHub issue in one command. The last two triage rounds (Sonos, HassQA) each turned into fixes within hours — and every fix carries its pinning test.
  • One-command test runs. flua --tool test discovers test_*.lua, runs each on the instant clock, one summary line, nonzero exit — the CI shell loop every project hand-rolled. --deadline SEC is the kill switch a hung test cannot survive.
  • A real linter, finally. flua --tool luacheck resolves the QA's whole file closure and runs the user-installed luacheck over it with the flua/HC3 globals whitelisted — output flags your undefined variables, not the noise of fibaro/api being "undefined". Three rounds of HassQA feedback took a multi-file QA from ~350 warnings to zero, with the genuinely undefined PCALL-class bugs left standing.
  • Trust the artifact. inspectFQA and pack --verify show exactly what a package contains — the second time an agent asked for it, it became a tool.

HC3 fidelity, quietly deepened

  • The type/interface schema is the law (ADR 0014) — device structures, property types and enums derive from the distilled HC3 schema; --tool typeinfo prints a type's implementation contract, and updateProperty now warns when a property the type does not declare would be silently ignored on the real controller.
  • Remote REST rides X-Fibaro-Version: 2 like the web UI; GET /icons serves the v2 type table for QAs; /devices?isTypeOf= follows the inheritance tree, matching live-verified HC3 behavior.
  • Uploads go through the HC3's web-import endpoint — the package-preserving path, multipart as a real file part; legacy UI exports match the HC3's own shape byte-for-byte.
  • WebSocket servers can push. net.WebSocketServer grew server-initiated frames, per-connection lifecycle events, and server-side disconnect — built for the Sonos offline suite, whose reconnect test caught a real long-standing bug.

The little things

  • json.encodeFormatted() for readable fixture dumps; --var KEY=VALUE overrides variables from the CLI; --deadline SEC as the run kill switch alias.
  • Sensor sim devices boot with a numeric value, never the skeleton's empty string — a whole class of value > threshold crashes cannot happen.
  • The icon manager probes the asset tree instead of trusting metadata; room/scene custom icons serve flat; icon families resolve through the type hierarchy.
  • Two WS flake fixes and one scene date-trigger race — the CI matrix is green again, and the fixes are the tests.
