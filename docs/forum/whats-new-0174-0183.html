What's new in flua — 0.1.174 through 0.1.183

Ten releases in a few days, and one theme dominates: QuickApp user interfaces grew up in flua — the modern elements, a paste-ready UI printer, and a proper model of how button presses actually become method calls on the controller. As usual, most of it exists because someone hit a wall first. (The button that did nothing — that story gets its own post, linked below.)

QuickApp UIs got modern

  • Tabs, collapsibles and images. The HC3's newer view format brings tabView (tabbed panels) and collapsible (expandable sections) — both now declared in plain --%%u: directives and rendered by flua's web viewer. Images join the classic buttons/sliders/switches, url or inline SVG (in the viewer — the HC3 app prefers plain http(s) art).
  • Live-verified on real controllers. Tabs and collapsibles were uploaded and exercised on actual HC3s: they render, they click, the callbacks fire. Two rules came back from the field: declare --%%useUiView:true (the old renderer shows a blank view), and never edit such a QA in the HC3's UI editor — it doesn't know the elements. flua's --check now warns about the first one.

How button presses actually work

Building the above forced the question: what exactly happens between a tap and your method running? The answer turned out to be a small three-case model — and one silent, maddening bug. The whole story, in plain language, is in the companion post The button that did nothing. The short version: the main QA has a callback table, children don't — their views name the method directly — and an empty argument list must be json.array() or the controller silently drops the press.

Paste-ready UIs for child devices

Child devices are the one place the HC3's editor never rewrites a UI — which makes them the natural home for tabbed panels. flua now prints any declared UI as a paste-ready Lua table (flua --tool ui --as-lua) that drops straight into createChildDevice, with the child-style bindings baked in. And a new --%%rsrc directive lets a QA declare its child UIs as named resources that flua injects at runtime and packages into a file automatically — we'll give that its own post soon, it deserves one.

Under the hood (for the tinkerers)

  • Loaded files see your QA's world. dofile now runs in the QA's own environment like require always did, and _FLUA.loadFile(path) is the sanctioned loader for test harnesses that drive a QA's real files at runtime — born from a field report by an agent building a test harness.
  • class() is documented. The return value is the parent-setter, the class object lives in the global, and every class needs its own __init__ — the HC3's actual contract, now written down instead of source-dive territory.
  • Smaller fixes that matter. The test runner's deadline is now its own wall clock; luacheck leftovers swept; the uploadable examples no longer crash a real HC3 on their keep-alive call.
