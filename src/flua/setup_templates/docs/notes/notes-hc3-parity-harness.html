HC3 parity harness — design

Verifying that flua behaves like the HC3, quirks and all, against a real controller. Planned (2026-11-04); the FluaHelper is the Tier-3 transport.

Cadence shapes the architecture

The harness runs rarely — every Fibaro FW release (and whenever a flua version claims new surface). So the controller must only be needed at capture time; everything after that is offline. Two artifacts:

  • capture — against the real HC3, produces checked-in fixtures;
  • replay — offline, deterministic, in CI forever, diffs the sim vs the fixtures.

Firmware upgrades become: parityCapture → review the printed delta → commit fixtures + any sim fixes.

The four layers

1. Shape probes (read-only, zero risk)

Auto-derive from routes/__init__.py's ROUTES table — the route registry is the single source of truth for what the sim implements; the --capabilities-json table stays the honesty surface, not the driver. Every implemented GET becomes a probe: {method, path with concrete ids, params, house-normalizer}. House-normalizers are mandatory (filter device lists by type, drop serial/hcName, replace ids with <id> placeholders) — the HC3 under test is a real house, values are not comparable.

Capture records status + normalized shape per probe; replay runs the same probe against the sim and reuses the existing problems-vs-gaps drift: problems fail (sim bug), gaps report (unmodeled fields — the sim is a subset).

2. Mutation probes (controlled, guaranteed cleanup)

A session-scoped artifact tracker: every probe creates only flua-p-<uuid8>-prefixed artifacts (QA, customEvent, globalVariable), registers them, and teardown deletes LIFO; --tool parityCleanup removes orphans from crashed captures. Settings PUTs snapshot and restore the old value (hcName!). Covers QA create/upload/call/updateProperty/delete, customEvents CRUD + publish, globalVariables add/change/delete.

Capture runs the sequence against the real HC3 and pins status + shape + id placeholders. Replay executes the same sequence against the sim (deterministic — seed house, no controller) and compares. This is what makes Tier 2 CI-able instead of HC3-gated. (Decided: the trade-off — capture pins are still real HC3 responses, only the replay execution is offline.)

3. QA runtime probes (what QAs observe)

Two directions, both enabled by the helper:

  • In-QA self-test: the probe QA (built on dev/apitest.lua, promoted to tests/hc3_parity/probe_qa/) is uploaded to the HC3 via the existing REST import and exercises api calls, updateProperty/updateView quirks, timers, emitted events — logging everything to /debugMessages. flua's /debugMessages is real, so the same QA runs in the sim and the harness diffs the two debug transcripts (normalized). Verifies the runtime as observed from inside a QA, not the REST response.
  • fibaro probes: for each fibaro.* entry in the capabilities table, api.helperFibaro(name, args) runs it controller-side in the helper's context. Capture pins return types and error semantics (nil-function behavior, bad-arg errors). Replay compares the sim's fibaro.* on the same house-independent args. The helper is exactly the Tier-3 transport the parked note was missing.

4. Quirk pinning

Every HC3 quirk discovered (updateView string values, selectedItem matching, 404-vs-400 behaviors, id reuse, restart semantics) becomes one behavioral test with the expectation captured from the real controller.

FW release workflow

  1. User upgrades the HC3 FW (their cadence, not ours).
  2. HC3_TEST=1 flua --tool parityCapture --fw 5.221 → writes tests/hc3_parity/fixtures/5.221/, prints the diff vs the previous fixture.
  3. Review the delta, three verdicts: flua bug → fix the sim; real HC3 change → update sim + fixture; house noise → extend normalization.
  4. Commit fixtures + fixes; the replay suite keeps it pinned in CI.

Replay defaults to the newest fixture; --fw pins an older one. Fixtures are keyed by softVersion only (decided).

Safety rails

Namespaced artifacts only (flua-p-*); never touch existing devices/globals; settings PUTs restore their old values; dry-run listing before capture; the existing auth-lockout guard stays. The existing opt-in live suites (test_hc3_live.py, test_hc3_compat.py) keep their role as quick smoke checks; capture is the new deep entry point.

Implementation order

  1. ~~Extract the shape oracle~~ — done: flua.parity.normalize (shape/drift), compat suite reuses it.
  2. ~~Capture tool + fixtures + replay suite~~ — done: --tool parityCapture (read-only, --dry-run, --fw, --fixtures), fixtures keyed by softVersion, tests/hc3_parity/test_hc3_replay.py replays offline (--parity-fw pins one fixture; without fixtures it skips; the comparison machinery is pinned by a synthetic-transcript test and the probe coverage by a route-registry test). First milestone complete: whole GET surface captured and replayed.
  3. ~~Mutation probes + artifact tracker + parityCleanup~~ — done: customEvents CRUD+fire+publish, globalVariables add/change/read/delete (pins the post-delete 404), QA lifecycle (create/read/updateProperty/ read property/delete — no Lua needed on either side; the HC3 .fqa vs sim {name} body asymmetry is modeled as an explicit per-side body). --mutations gates the capture-side sequences; teardown is LIFO via the tracker; --tool parityCleanup lists/deletes flua-p-* leftovers (prefix-guarded). Replay runs the same sequences against an engine-backed sim and compares status + shape per step. Deferred: the settings PUT snapshot/restore probe — it changes real controller state and deserves its own deliberate run, not a default.
  4. ~~Probe QA (debugMessages transcript diff) + helperFibaro probes~~ — done: --probe uploads tests/hc3_parity/probe_qa/main.lua to the HC3, records its tag-filtered, whitespace-normalized /debugMessages transcript, deletes the QA; replay runs the same QA in the sim and diffs line by line (determinism pinned by a double-run test). --fibaro runs the house-independent helperFibaro probes (getName-no-args, getGlobalVariable-absent, getSelfId, nope) controller-side and pins ok + value shapes; replay calls the sim's fibaro table with the same args. First finding: the HC3's getName requires a deviceId too (the sim's check was right); getGlobalVariable blocks in the helper's net-callback context (flagged unreachable — the in-QA probe pins the contract).
  5. Quirk pinning as discoveries surface during capture runs.

First capture — drift ledger (5.221.21)

The first full capture + replay round found and fixed (commits fe6a0a3–def7ffc):

  • names validated [A-Za-z][A-Za-z0-9_]* (customEvents/globalVariables create 400, customEvents name routes 501 — the HC3's handler quirk); the harness prefix is now flua_p_<hex>;
  • customEvents create 201; fire/publish/delete on absent names 204 (idempotent — the sim's 404 contradicted the HC3); update absent 404;
  • globalVariables create 201 + full dto; delete 200 (idempotent);
  • POST /quickApp 201; DELETE /devices/{id} 200;
  • QA-context api layer: unknown routes 501, GET /plugins/{id} 501 (even own id), /plugins/updateProperty 400 for other callers (own QA or parent only); user-registered endpoints keep their own contracts;
  • QuickApp has no getProperty/getView on the HC3: getProperty removed, getView kept as a documented flua extension (the DX helpers use it);
  • /plugins is the plugin-type catalog on the HC3 (the sim lists its QA devices offline — known divergence, catalog modeling deferred); online mode passes the controller's answer through;
  • shape fixes: /refreshStates has no events key when idle (the harness drains the replay feed), /weather drops WeatherConditionConverted, scenes keep 'running' as a documented extension, /profiles/{id} drops 'active', /panels/notifications is a list;
  • capture-side: probe transcript keyed by the HC3's QUICKAPP tag and order-insensitive, helper wake runs in a worker thread, helper transport failures flagged unreachable.

House-state-dependent: /panels/family and /panels/humidity answer 501 on this house (no such panels) — known-drift entries. The full replay suite is green against the checked-in fixture: 65 offline tests pin the 5.221.21 contract.

Deferred: the settings PUT snapshot/restore probe, and modeling the /plugins plugin-type catalog in the sim.
