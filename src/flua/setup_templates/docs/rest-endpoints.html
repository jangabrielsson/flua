flua REST endpoints — real vs stub

Which simulated endpoints carry real data and which are HC3-shaped stubs. The classification rule (from docs/notes/notes-rest-parity.md): implement a stub for real only when (a) a QA calls it, (b) a tool/agent reads it, or (c) the compat suite flags shape drift.

The stub column is machine-readable: SHAPE_ONLY_ROUTES in src/flua/api/__init__.py is the source of truth (update both together), flua --capabilities-json serves it as the rest table (status: state | stub | extension), and the runtime warns on first use of a stub (default on; --%%warn:stubApi=false silences).

Area Real (state-backed) Stub (shape-only: empty/zeroed)
Devices CRUD (POST /devices = base device from the type skeleton, flua extension; GET/PUT/DELETE /devices/{id} — PUT: name/visible/enabled/roomID + a merged properties dict, all restart the QA; PUT /devices/{id}/properties/{name} restarts too), actions, groupAction, /flua/devices —
Plugins variables, child devices, views, restart, UI events, /flua/embeddedUI —
House scenes, rooms, sections, globals, alarm partitions, profiles, customEvents (CRUD + {name}/publish; firing uncreated events 404s), /home (+ PUT) /iosDevices, /alarms/v1/devices, /notificationCenter, /energy/devices
Panels /panels/location (+ PUT {id}) /panels/climate, /panels/{id}, /panels/notifications, /panels/family, /panels/sprinklers, /panels/humidity, /panels/favoriteColors
Logs & feeds /refreshStates, /debugMessages (+ tags, DELETE), /flua/systemLog (+ DELETE) —
System /settings/info (+ PUT), /settings/location (+ PUT), /weather, /quickApp/* (files/export), /proxy, /diagnostics, /icons (the checked-in controller icon catalog — devices/icons.json, scraped from the HC3; ?deviceType= filters to the type's icon sets, unknown types 404) /users

Notes:

  • Stubs still answer 200 in the HC3's response shape — they are shape-compatible by design (the live compat suite pins that), they just carry no data.
  • /flua/* routes have no HC3 counterpart — they are the flua-only machine surface (/flua/devices, /flua/embeddedUI, /flua/systemLog, /flua/icons/{set}/{file} — the icon cache channel, /flua/iconMap — the deviceIcon id→set lookup + per-set file lists for state switching).
  • PUT /weather is a flua extension — the HC3's weather is provider-owned and read-only; the sim lets a test QA override it (merging per field; each changed field emits a WeatherChangedEvent).
  • The full HC3 surface is much larger than this table (359 endpoints in docs/specs/hc3-api.json); the sim implements the slice QAs, tools, and the viewer actually touch — the rest forwards to the HC3 online.
